An app in Brainstorm is two files. A `manifest.json` that says what it is called
and what it is allowed to touch, and an `index.html` that draws it. There is no
bundler, no package.json, no install step, and nothing to compile.

That was already true, but there was no way to act on it from inside the product.
Now there is. Open the Code editor, write those two files, select them, and choose
Install as app. It lands on your dashboard immediately, no restart, and it reads
your vault through the same permissions any other app gets. If a folder on disk is
easier, or someone hands you a `.brainstorm` bundle, those install too.

You do not have to write the code yourself either. Ask the agent for the app you
want and it drafts the files as cards. You read them, edit the paths if you like,
and approve. Nothing is written to your vault before you do, which is the same
deal as every other thing the agent proposes.

An app you install this way is unsigned, and Brainstorm says so plainly rather
than pretending otherwise. It gets the capabilities you grant it and none besides.

## Sharing shows people now

If you shared something with a teammate, half the time you saw a long
`ed25519:` string where a name should be. Now you see the name. It travels with
the object itself, inside the same encryption everything else uses, so there is no
directory of users anywhere and the relay learns nothing new about who you work
with.

The key fingerprint still sits next to the name. A display name is only what
someone calls themselves, so it should never be the only thing telling two people
apart.

Three fixes are worth naming. Sharing a channel used to drop messages on the way
across, silently, and now brings the whole conversation. An invite code opens
exactly one thing, one time, and expires on its own. Revoking someone takes effect
straight away.

Elsewhere: a file the agent proposes at a path you already have asks what you want
instead of quietly making a second copy, the Code editor's right panel stays still
while you type, and its file tree has folders.

macOS builds are signed with a Developer ID and notarized by Apple, so they open
without a Gatekeeper warning. Windows is currently unsigned, so you may see a
SmartScreen "unknown publisher" prompt, where the option you want is **More info**
then **Run anyway**. Existing installs update in-app from **Settings → Updates**.

It is still a beta, so keep backups of anything important. Your vault is a plain
folder you control completely.
